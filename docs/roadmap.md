## 架构决策记录

### ADR-001：人在环中（HITL），不做全自动

**决策**：Agent 在每个关键节点（拆题、选模、定参数）抛出候选方案 + 理由，由用户拍板后继续。

**理由**：全自动方案（输入赛题 → 输出论文）实现上就是一条长 prompt 串代码执行，
看起来震撼，但绕开了 Agent 工程真正困难的部分。「中断-决策-恢复」才是最有价值的技术点。

### ADR-002：HITL 用「状态落盘 + 点击时重建」

**决策**：每个节点跑完即把状态存入 SQLite；用户决策后从 checkpoint 重建上下文继续。

**理由**：进程内挂起（await 一个 Future）实现简单，但服务重启就丢进度、无法水平扩展。
落盘式的代价是复杂度，换来的可恢复性和可部署性值得。

**推论（重要）**：checkpoint 的 schema 必须在 M1-M2 就定下来，不能拖到 M4 ——
整个编排层是围绕它生长的。

### ADR-003：Provider 抽象层，内部统一用 OpenAI 格式

**决策**：定义归一化的流式事件模型；内部消息格式直接采用 OpenAI 的 chat 格式。

**理由**：实测 DeepSeek / 通义 / Kimi / Ollama / vLLM 全部兼容 OpenAI 协议，
用它当内部标准意味着只有一个 Provider 需要写真正的转换代码（Anthropic）。

**已知代价**：OpenAI 的概念会渗透到上层状态机。这是被接受的取舍，不是疏忽。

### ADR-004：Provider 层不做重试

**决策**：一旦流开始吐字节，出错就产出 `ErrorEvent` 并结束，绝不自动重试。
连接建立**之前**的失败由 SDK 的 `max_retries` 处理。

**理由**：流一旦开始就无法回滚。重试会让用户看到前半句被重复输出。
而且只有上层状态机知道当前跑到哪一步、用户等了多久，重试决策权归它。

**实现**：`ErrorEvent.retryable` 字段把这个判断的结论一并交给上层。

### ADR-005：沙箱必须使用独立运行时环境

**决策**：执行 LLM 生成代码的沙箱**不得**与后端共用 `.venv`。
因此 `pyproject.toml` 里刻意没有 numpy / scipy / matplotlib。

**理由**：同一个环境里跑不可信代码，等于把整个项目和 API Key 都交出去
（`os.environ["DEEPSEEK_API_KEY"]` 一行就能读走）。这不是洁癖，是安全边界。

**推论**：沙箱环境在 M3 单独创建。

### ADR-006：图表与 UI 共用一套色彩体系

**决策**：`web/src/app/globals.css` 是全站视觉的唯一真相来源。组件内禁止硬编码色值。

**理由**：ModelForge 是图表密集型产品。UI 一套色、图表另一套色，成品会像两个产品拼起来的。

**硬性约束（由配色校验计算得出，非审美偏好）**：
- 亮色模式下有 3 个分类色对比度低于 3:1 → 图表必须带**直接标签或表格视图**
- 暗色模式最差相邻 CVD ΔE = 10.3（危险区）→ **必须启用次级编码**（标签/间隙/纹理）

**合起来**：图表永远不能只靠颜色区分系列。

### ADR-007：Agent 自称「蒟蒻」

**决策**：Agent 在文案中自称「蒟蒻」（网络语，新手、菜鸟）。

**理由**：与 ADR-001 自洽 —— 一个承认自己拿不准、每个决策点都停下来问用户的 Agent，
自称越谦逊，交互越不违和。这个调性延续到 Agent 提示词和各处界面文案。

## M2 计划：SSE 流式协议

### 目标

把 M1 产出的事件流推送到浏览器，让 Agent 的思考过程逐字显示。

### 一个必须先解决的问题：EventSource 发不了 POST

浏览器的 `EventSource` API **只支持 GET 请求，不能带请求体**。
但我们要把消息列表发给后端，这天然是 POST 语义。两条路：

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（倾向）** | 用 `fetch` + `ReadableStream` 手动解析 SSE 帧 | 现代标准做法，完全可控。代价：要自己写 SSE 解析（约 30 行），且不能自动重连 |
| B | 先 POST 创建会话拿到 id，再 `EventSource` GET 那条流 | 能用上 EventSource 的自动重连。代价：多一次往返，且流与首次消息的创建耦合 |

**待定** —— 动手时再权衡。这不是知识题，是取舍题。

### 后端

- `modelforge/api/stream.py`：SSE 端点
- SSE 帧格式：`event: <type>\ndata: <json>\n\n`
- 事件体直接用 `event.model_dump_json()` —— 这正是 M1 用 Pydantic 的回报

### 前端

- `web/src/app/` 下新增流式视图
- 复用 M0 已验证的状态机思路，但把 `loading` 从「转圈」换成「文字在流动」

### 验收标准

- [ ] 页面上文字逐字出现，不是等几秒后整段蹦出
- [ ] 工具调用时，界面上出现对应的状态提示
- [ ] 后端挂掉时，前端显示明确错误而非白屏
- [ ] 断开后重连不产生重复文字

## 环境备忘

- `.venv` = Python 3.12.4（从 Anaconda base 的 python.exe 创建）
- **系统 PATH 里的 `python` 是 3.7（已 EOL）**，一切操作必须显式用 `.venv/Scripts/python.exe`
- pip 清华镜像配置在 `.venv/pip.ini`（在 venv 内，被 gitignore）
- `.env` 按**当前工作目录**查找，所以命令必须在项目根目录执行
- 从 PowerShell 传中文参数给 Python 是安全的（已验证码点无损）

### 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| `WinError 10013` | 端口被占用（报错信息完全没提这点） | `netstat -ano \| findstr :8000` 拿 PID → `taskkill /F /PID <pid>` |
| 前端跑到 3001 端口 | 3000 被占 | **必须在 3000**，因为 CORS 白名单只放行了它 |
| `ModuleNotFoundError: modelforge` | editable 安装的查找器映射为空 | 在项目根目录重跑 `pip install -e .` |

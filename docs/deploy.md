# 让别人用起来

这份文档回答两个问题：**别人怎么跑这个项目**，以及**为什么没有公网演示**。

先说清定位，因为后面所有取舍都是从它推出来的：

> 这是一个 **HITL（人在环中）的参考实现**，面向数模比赛的完整流程
> ——读题、拆解、选模、求解、验证、成文——但每一步的判断权都留给使用者。
> 它的价值在**怎么设计**，不在**服务多少人**。

所以下面这几节不是在解释「有哪些没做完」，而是一次排过序的取舍。
「想过、权衡过、决定不做」和「忘了做」是两回事 ——
而**知道边界的弱点**，和 README 里那段「沙箱能挡什么、挡不住什么」
是同一条原则。

---

## 一、有哪几种「别人用你的项目」

门槛差一个数量级，覆盖的人群也完全不同。

| 模式 | 对方要做什么 | 能覆盖谁 |
|---|---|---|
| **A. 自己跑** | 照着下面那份清单来 | 愿意花半小时的人 |
| **B. 打开一个网址** | 点开 | 所有人 —— 但代价见第三节 |

## 二、模式 A：对方自己跑（清单）

> 下面这份清单是**手工版**。M6b 里那个 Docker Compose 要做的事，就是把它
> 压成一条 `docker compose up` —— 体验完全一样，只是少走七步。

### 前置

- **Python 3.12+**（不是 3.11，`pyproject.toml` 里写死了 `>=3.12`）
- **Node 22+**
- 一个模型 API Key。默认是 DeepSeek，[在这里申请](https://platform.deepseek.com/)。
  也可以用 Ollama 跑本地模型（不用 Key，但要在 `.env` 里改 `DEFAULT_PROVIDER`）

### 七步

```bash
# 1. 克隆
git clone https://github.com/nanfengjunhuai/modelforge.git
cd modelforge

# 2. 后端环境
python -m venv .venv
.venv/Scripts/activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -e ".[dev]"

# 3. 前端依赖
cd web && npm install && cd ..

# 4. 配置模型
cp .env.example .env
#    然后打开 .env，把 DEEPSEEK_API_KEY 填进去
```

```bash
# 5. 沙箱环境（⚠️ 见下面那段，这步不能跳过）
.venv/Scripts/python scripts/setup_sandbox.py --mirror
```

```bash
# 6. 起后端（在项目根目录，:8000）
.venv/Scripts/python -m uvicorn modelforge.main:app --reload --port 8000
```

```bash
# 7. 起前端（另开一个终端，必须在 :3000）
cd web && npm run dev
```

然后打开 <http://localhost:3000/chat>。

> `--mirror` 用的是清华 PyPI 镜像。国内网络下不加它会很慢或直接超时；
> 如果你的网络通畅，去掉它也行。

### ⚠️ 第 5 步为什么不能跳过

沙箱跑的是**模型生成的代码**，也就是不可信代码（ADR-005）。它必须在一个
**和后端完全隔离的 Python 环境**里运行 —— 共用一个环境的话，
一行 `os.environ["DEEPSEEK_API_KEY"]` 就能把密钥读走。

所以 `pyproject.toml` 里**刻意没有** numpy / scipy / matplotlib。
那不是遗漏，是安全边界。跳过这步的后果是：模型一跑代码就说
「解释器不存在」，而这个报错看起来像装错了东西，不像安全问题。

### ⚠️ 中文 Linux 用户注意字体

沙箱里的 matplotlib 用 `Noto Sans SC` 画图，在 Linux 上要装：

```bash
sudo apt install fonts-noto-cjk      # Debian / Ubuntu
```

**不装的话 matplotlib 不报错** —— 它只是安静地退回 DejaVu，
于是图里所有中文变成方框（豆腐块）。这和 README 里写的那条是同一种坑：
不报错的错最难查。装完之后把 PNG 打开看一眼再下结论。

### 数据落在哪

| 东西 | 位置 |
|---|---|
| 会话与事件日志 | `data/modelforge.db`（已 gitignore，删掉等于清空所有会话） |
| 图表、报告等产物 | 系统应用数据目录下的 `modelforge/artifacts/` |
| 沙箱临时目录 | 系统临时目录下的 `modelforge-sandbox/`（用完即删） |
| matplotlib 字体缓存 | 系统应用数据目录下的 `modelforge/mplconfig/` |

⚠️ **产物目录刻意不在项目里** —— 放进去的话，每生成一张图都会触发 uvicorn
的 `--reload`，而重载信号会打断正在执行的沙箱代码，表现为随机的
`KeyboardInterrupt`，且只在画图那几轮出现。看起来像「模型偶尔抽风」。
想换位置请用环境变量 `ARTIFACTS_DIR`，别改回 `artifacts/`。

### 先确认它真的能用

```bash
.venv/Scripts/python scripts/smoke_stream.py "用三句话解释什么是熵权法"    # 流式
.venv/Scripts/python scripts/smoke_artifact.py                          # 出图 + 产物链路
.venv/Scripts/python scripts/smoke_report.py                            # 报告生成
```

三个脚本都会用真实模型、把产物下载到 `.smoke/`，并且**最后都有一眼要人看**
（图好不好看、报告读起来像不像论文）—— 那部分脚本验不了。

## 三、模式 B：公网部署 —— **有意不做**

结论：**不做。** 不是没时间，是权衡之后判断它对**这个项目**是负收益。

### 理由一：它往往是负分，不是加分

简历项目放一个公网地址，收益是「对方不用装环境就能看到」。但：

- 面试官点开看到 502、或者转八秒没反应 —— **比没有网址更伤**
- 免费托管多半会休眠，第一个访问的人要等十几秒冷启动
- 而这些失败模式全都不在你的控制里

### 理由二：这个项目有两件已知应付不来的事

**① 沙箱是「防误伤」级，不是「防蓄意攻击」级。**

README 里那张表写得很清楚：它挡得住读走后端密钥、误删项目文件、
死循环卡死后端；**挡不住**用绝对路径读任意文件、发网络请求、把 CPU 跑满。

**这是为「用户自己跑自己模型的输出」这个场景设计的。**
一旦放到公网上，就变成了「任意陌生人可以在你的服务器上跑任意 Python」——
那需要容器或微虚拟机级别的隔离，是另一套实现，不是调几个参数。

**② 没有鉴权。**

任何人打开你的网址都在**烧你的 API 额度**。ADR-008 当初选
`fetch` + `ReadableStream` 而不是 `EventSource`，理由之一就是
「M6 要加鉴权时 `fetch` 能直接加 `Authorization` 头」——
路是留着的，但没走。

### 理由三：国内可达性是个真问题

`vercel.app` 整片不可达，而免费 PaaS 里能跑长期进程 + 持久化磁盘的那几家
（Railway / Render / Fly.io）在国内的访问都不稳定。真要稳定就得用国内云服务器：
学生认证约 10 元/月，不认证约 60–100 元/年，还要自己续费、配域名。

### 如果哪天真的要上，该做什么

按依赖顺序：

1. **换隔离方式** —— `sandbox/base.py` 是一个协议，换成容器或微虚拟机
   不需要改上层任何代码。这是当初把它做成协议的原因
2. **加鉴权** —— 在产物和会话这两个路由组上加一层依赖（`api/artifacts.py`
   的模块注释里写了为什么走显式路由而不是 `StaticFiles`：就是为这个留的）
3. **设成本上限** —— 每个会话的 token 预算
4. **持久化卷** —— SQLite 文件和产物目录都要挂出去，否则重启就清零，
   「刷新不丢」这条卖点直接没了

**在 1 和 2 做完之前，不要把它暴露到公网。**

## 四、模式 C：截图

最省事、覆盖最广。一张能说明问题的图胜过一份七步清单。

该拍什么（按信息量排序）：

1. **决策卡片那边** —— 蒟蒻停下来问、候选方案摆在卡片上。
   这是「人在环中」唯一的视觉证据，也是最难用文字讲清楚的一点
2. **一张论文级的图 + 右边面板里同一份数据的交互图** —— 「图和数字同源」
   这一条，两张图并排就讲完了
3. **报告里那段「过程记录」块** —— 带着用户当时的选择和备注。
   这是事件日志这个选型最直观的回报

## 五、还没验证的一件事

**`next build` 从来没跑过。** 开发全程用的 `next dev`。

生产构建能不能过是**没人验证过的** —— 它可能一次性通过，也可能炸在某个
只在 `next build` 下才走的代码路径上。这件事独立于上面的部署决策：

- 如果你只是想让别人本地跑（模式 A），`npm run dev` 就够，不受影响
- 如果哪天要构建一个可交付的版本，**先单独跑一次 `next build`**，
  别把它和别的事情混在一起做

⚠️ 跑它会动 `web/.next/` 目录，而 `next dev` 正在盯着那里 —— **先停掉
前端 dev 服务器**再跑。另外在临时目录里构建是行不通的（Turbopack 不接受
指向项目根之外的 `node_modules` 软链接），只能在 `web/` 里构建。

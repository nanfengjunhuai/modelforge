# ModelForge · 模型工坊

> 人在环中的数学建模 Agent 工作台。

输入一道数学建模赛题，多个 Agent 协作推进——拆题、选模、求解、验证、成文。
但**每个关键决策点它会停下来问你**：怎么拆题、选哪个模型、参数怎么定。你拍板，它执行，全程可见。

## 为什么不是「一键出论文」

全自动方案（输入赛题 → 输出论文）实现上就是一条长 prompt 串起代码执行，
看起来震撼，但**没有解决 Agent 工程真正困难的部分**。

ModelForge 选择做难的那一半：

- **中断与恢复** — Agent 在决策点停下来问你，状态落盘；你拍板后从事件日志重建
  上下文继续跑。刷新页面不丢，服务重启不丢，支持多会话并行。
- **可观测** — 每一步的推理流、工具调用、代码执行结果都实时推给前端，不是黑盒。
  用户做过的每个决策也结构化地记下来，不是混在聊天文本里。
- **产物可带走** — 它画出来的图是**能直接贴进论文**的：论文风格、矢量输出、
  字体已嵌入、黑白打印也分得清系列。图和数据一起落盘，刷新不丢、可下载。
- **安全执行** — LLM 生成的求解代码在**独立于后端的环境**中运行，带资源限制与超时。

## 中断与恢复是怎么做的

> 这一节讲的是这个项目最核心的那个技术点。想直接玩的话跳到下面的「快速开始」。

「人在环中」听起来像是个交互设计问题，其实是个**状态管理**问题：
Agent 在决策点停下来之后，那部分正在跑的推理该放在哪？

最容易想到的做法是「在进程里挂起一个 Future，等用户答完再唤醒」。实现简单，
但它有三个绕不过去的毛病：服务一重启进度就没了、没法多开一个进程、
而且那个挂起的东西是**不可观测的**（你没法问它「你现在在等什么」）。

ModelForge 的做法是**状态落盘 + 点击时重建**：

```
   模型调用 ask_user
        ↓
   如实记录一条「还没有结果的工具调用」→ 结束这条流
        ↓
   （进程可以退出、重启、换机器）
        ↓
   用户拍板 → 答案 append 成一条事件
        ↓
   从事件日志重新投影出完整的消息历史 → 重新跑一次 Agent 循环
```

三个由此得到的性质：

**① 恢复路径里没有一行「恢复」代码。** 它就是「用重建出来的历史重跑一遍」。
这是把状态交给事件日志之后免费拿到的，不是额外写的功能。

**② 「换个模型再算一遍」是免费的。** 因为日志只能 append，
「回到第 3 步改主意」= 从那条决策之前截断、重放。这是数模场景的高频动作 ——
而快照式的状态存储做不到这件事。

**③ 重试也是免费的。** 上一轮跑到一半断了？`POST /sessions/{id}/resume`
什么都不追加，照着当前历史重开一条流就行。

**为什么用事件日志而不是快照？** 快照只能回答「现在是什么」，
日志能回答「当时为什么」。而对一个要帮你做建模决策的工具来说，
**「你当时为什么选了 AHP」和「你选了什么」一样重要**。

**明确的代价**：日志只能 append，所以将来的「回退」必须是
「从某条决策之前截断，**连同其后所有事件一起丢**」。截一半会得到一段非法历史。
另外用户中途刷新时，被中断的那一轮**已经流出去的文字会消失**（一轮生成只在
跑完时才落盘）。这些都是被接受的选择，不是疏忽 —— 详见
[`docs/roadmap.md`](docs/roadmap.md) 的 ADR-009 / ADR-010。

## 图是怎么出来的

数模的产出物就是**图** —— 论文里那些插图才是用户真正要拿走的东西。
所以 M5 把这条链路当产品的一部分做，而不是「调个 matplotlib 完事」。

**风格靠环境保证，不靠模型自觉。** 最容易走偏的做法是「提供一个漂亮的 API，
指望模型每次都调用它」。模型会忘，忘了不报错，只会安静地出一张宋体豆腐块
（中文变方框、负号变方框、白底无网格），而你会以为是 matplotlib 的锅。

所以沙箱的 `MPLCONFIGDIR` 指向一份仓库里的 `matplotlibrc` ——
**沙箱里任何 matplotlib 代码都会自动套上论文风格**，模型一行都不用改：

- 中文黑体 + 西文无衬线，负号正常显示
- 去掉顶部和右侧边框、发丝网格压在数据下面、图例无外框
- 300 dpi PNG（贴 Word）+ 矢量 PDF（**字体以 TrueType 嵌入** ——
  很多期刊的投稿系统会直接拒收 Type 3 字体的 PDF）
- 配色是设计系统那一套（和界面同源，见 ADR-006）
- `mp.style_lines(ax)` 再叠一层线型和标记形状 —— **数模论文经常黑白打印**，
  那时颜色区分度归零，只有线型还能把曲线分开

**产物靠约定目录，不靠模型申报。** 代码把文件写进 `artifacts/`，执行结束时
被扫走；「让模型显式声明它产出了什么」是不可行的 —— 它一定会忘，
忘了还不会报错。模型只要**写文件**就行，那是它本来就在做的事。

**图和数字同源。** `mp.save(fig, name, chart={...})` 在存图的同时写一份
`<name>.chart.json`，里面是**模型算出来的真实数组**（直接吃 numpy 数组），
不是让模型把数字重新打一遍。工作台据此渲染可交互版本 ——
同一个数组，两个视图，数字不可能对不上。

**屏幕上的那一份是交互的。** 点开右侧「产物」栏里的
`<name>.chart.json`，同一个数组会渲染成一张可悬停的 ECharts 图，
旁边有一个**数据表**开关 —— 提示框不能是读到数值的唯一途径
（触摸屏上没有、被截图进论文里也没有）。

交互图**不直接用** `.chart.json` 里那份颜色。那份是配合**白纸**选的
（论文印出来用）；屏幕上的一份从 `--chart-cat-*` 实时取，
所以系统切到暗色模式时它会**当场**换色 —— 而暗色模式是重新选过步号的，
不是把亮色反转。两套色同一个来源（`globals.css`），所以对得上。

折线还叠了一层「线型 × 标记」：数模论文经常黑白打印，那时候颜色
区分度归零，只剩线型能把曲线分开。屏幕上留着它是为了让两个视图
讲同一个故事。

**明确的代价**：`.chart.json` 里带的是**亮色那一套**颜色，只在
「读不到设计令牌」时兜底。所以万一 CSS 没加载好，你看到的是一张
用纸用配色的图 —— 偏暗一点，但仍然是设计系统里的颜色，不是编出来的。

**明确的边界**：产物落在**系统应用数据目录**，不是项目里的 `artifacts/`。
这是踩过坑的 —— uvicorn 的 `--reload` 盯着项目目录，产物一落盘就触发热重载，
而重载信号会打断正在跑的沙箱代码。而且这个坑比 M3 那个更难发现：
沙箱的 `solution.py` 每次都触发（必中），产物只在画图时才落盘（偶发）——
竞态 + 低频 = 看起来像「模型偶尔抽风」。

试一下：

```bash
.venv/Scripts/python scripts/smoke_artifact.py
```

它会建一个真会话、让蒟蒻真的画一张图、把产物从 HTTP 接口下载到 `.smoke/`，
然后提示你打开看看。**最后那一眼必须人看** —— 脚本检查不了好不好看。

## 沙箱：能挡什么，挡不住什么

模型生成的代码是不可信的，所以它跑在一个独立的 Python 环境里
（**不是**后端自己的 `.venv` —— 否则 `os.environ["DEEPSEEK_API_KEY"]` 一行就能把密钥带走）。

**挡得住**：读走后端密钥 · 误删项目文件 · 死循环卡死后端 · 输出撑爆上下文

**挡不住**：用绝对路径读任意文件 · 发网络请求 · 把 CPU 跑满（超时能杀，但杀之前那几秒是实打实占着的）

**这是「防误伤」级别，不是「防蓄意攻击」级别。** 对「用户自己跑自己模型的输出」
这个场景够用，但**如果要做成多用户在线服务，这套实现必须整个换成容器或微虚拟机**。

之所以把这段写在 README 而不是只写在代码里，是因为**知道边界的弱点是工程的一部分**；
把它藏起来才是问题。执行器本身是一个协议（`sandbox/base.py`），
换隔离方式不需要改上层任何代码。

## 快速开始

> 正在开发中。以下命令针对 Python 3.12 + Node 22。

```bash
git clone https://github.com/nanfengjunhuai/modelforge.git
cd modelforge

# 后端
python -m venv .venv
.venv/Scripts/activate        # Windows
pip install -e ".[dev]"

# 前端
cd web && npm install && cd ..

# 配置模型（复制后填入你的 API Key）
cp .env.example .env
```

```bash
# 沙箱环境（跑模型生成的代码用的，和后端环境隔离 —— 见 ADR-005）
.venv/Scripts/python scripts/setup_sandbox.py

# 后端（在项目根目录，:8000）
.venv/Scripts/python -m uvicorn modelforge.main:app --reload --port 8000

# 前端（另一个终端，:3000）
cd web && npm run dev
```

然后打开 <http://localhost:3000/chat>，先试一道**需要做选择**的题：

> 我有一组评价类问题的数据，指标都齐全，帮我选一个赋权方法

你会看到它先跑一段代码探一探数据，然后**停下来问你** —— 卡片上摆着几个候选方案
和各自的代价。点一个，它接着往下算。

验证「刷新不丢」：**中途刷新浏览器**，历史、决策卡片、你选过的答案全都还在。

左边那一栏是这个工作台的全部会话，可以来回切、可以删（两步确认，
删会话会连同它的产物文件一起删掉）。

再试一道**让它画图**的（这是 M5 的重点）：

> 我有一组评价数据，8 个评价对象、4 个指标（都是效益型，越大越好）：
> [[12,30,45,20],[8,25,50,18],[15,28,40,25],[20,35,38,22],
> [9,22,44,30],[17,31,47,19],[13,27,42,28],[11,33,36,24]]
> 请用熵权法算出权重，并画一张论文里能直接用的插图。

它会跑代码算出权重，然后在工具卡片里给你一张**能直接贴进论文**的图：
中文黑体、去掉顶右边框、淡网格、柱顶标着数值。点开图能看大图、能下载。

然后看一眼**右边那一栏**：这张图连同它背后的数据都在清单里。
点那条 `.chart.json`，同一个数组会渲染成一张可悬停的交互图 ——
把系统切到暗色模式，它会当场换色；点「看数据表」，数值和图上标的是同一份。

⚠️ **如果它反过来问你问题，那是对的。** 数模题常常自带分岔口（样本量太小
导致方法退化、两个口径算出相反的结论），方法没定就先画图才是错的。
在卡片上拍板，它接着画。

纯计算验证沙箱：

> 用 numpy 算 1 到 100 的平方和，再开平方根

命令行验证流式输出（而不是攒完一起发）：

```bash
.venv/Scripts/python scripts/smoke_stream.py "用三句话解释什么是熵权法"
```

命令行验证整条产物链路（建真会话 → 真模型画图 → HTTP 下载）：

```bash
.venv/Scripts/python scripts/smoke_artifact.py
```

### 数据落在哪

| 东西 | 位置 | 说明 |
|---|---|---|
| 会话与事件日志 | `data/modelforge.db` | 已 gitignore。删掉等于清空所有会话 |
| 图表等产物 | 系统应用数据目录下的 `modelforge/artifacts/` | Windows 是 `%LOCALAPPDATA%\modelforge\artifacts`。删会话会一并删掉 |
| 沙箱临时目录 | 系统临时目录下的 `modelforge-sandbox/` | 每次执行一个子目录，用完即删 |

⚠️ **产物目录刻意不在项目里。** 放项目里的话，每生成一张图都会触发 uvicorn
的 `--reload`，而重载信号会打断正在执行的沙箱代码 —— 表现为随机的
`KeyboardInterrupt`，且只在画图那几轮出现，看起来像「模型偶尔抽风」。
想改到别处请用环境变量 `ARTIFACTS_DIR`，别改回 `artifacts/`。
